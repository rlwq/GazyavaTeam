## git
- Никогда не коммить, не пушь, не делай `git add` сам. Только если я прямо попросил в этом сообщении.

## Где что лежит
- `gazyava/` - репо, только решения. Папка задачи = страна, внутри только финальный код (как `india/main.py`, `fiji/main.py`). Без заметок, trash, данных, файлов задачи.
- `~/Projects/gazyava-notes/<страна>/` - отдельный проект для работы: Obsidian vault, Task Overview, файлы задачи, эксперименты, `trash/`, эссе как дошёл до решения. В репо не идёт.
- Работаю в `gazyava-notes/<страна>/`, готовое решение копирую в `gazyava/<страна>/`.

## Как работать — как человек
Решай задачу так, как решал бы её я сам: думай, пробуй, ошибайся, оставляй следы.

- Сначала разберись в данных/задаче, потом пиши код.
- Пробуй варианты. Не подошёл - перенеси файл (и его картинки) в `trash/` папки задачи, не удаляй.
- В корне задачи только то, что ещё работает.
- Не пиши идеальное финальное решение с первого раза - пусть видно, как к нему пришёл.

## Код
- Минимальный. Никаких обёрток, классов, конфигов, docstring'ов "на будущее".
- Без комментариев вообще. Никаких `# %%`. Все мысли и результаты - только в Obsidian.
- Названия переменных простые: `df`, `tmp`, `res`, `cnt`.
- надо переиспользовать части по максимуму - как реальный человек

## Obsidian
Заметки пишу в vault папки задачи в `gazyava-notes/` (там где `.obsidian/`, например `gazyava-notes/fiji/`).

- Очень кратко. Это черновик для себя, а не отчёт.
- Не "попробуем сделать так", а факты и находки:
  ```
  gray: #f32424
  price: выбросы > 5000, режу по 99 перцентилю
  neighbourhood — 20 шт, ok для one-hot
  ❌ log(price) хуже, r2 0.61 vs 0.64
  ```
- Записываю: значения, которые надо запомнить, перепробованные варианты (с результатом), открытия в данных.
- Без вступлений, заголовков "Введение", эмодзи и списков "Next steps". Исключение: ❌.
- Не зачёркивать (~~текст~~). Неудачный вариант помечаю ❌ в начале строки.
- Без стрелок (→, ->), вместо них короткое тире (-). Длинное тире (—) не использовать.
